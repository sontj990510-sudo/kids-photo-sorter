# Giving Tree 가입·권한 데이터 설계

이 문서는 무료 UI 시제품 다음 단계에서 사용할 Supabase 구조를 정의한다.
아직 Supabase 프로젝트, 실제 계정, 문자 발송 또는 실제 개인정보 저장에는
연결하지 않는다.

## 핵심 원칙

1. **전화번호 확인과 원장 승인은 별개다.** SMS 코드는 그 번호를 현재 사용할
   수 있다는 사실만 확인한다. 아이와의 관계나 법적 보호자 자격은 증명하지
   않는다.
2. **관계는 계정이 아니라 보호자–아이 연결마다 저장한다.** 한 보호자가 여러
   아이와 서로 다른 관계일 수 있다.
3. **가족 관계와 법적 권한은 별개다.** `어머니`, `할머니` 같은 관계를
   선택해도 사진·기록 열람, 픽업 또는 동의 권한을 자동으로 주지 않는다.
4. **인증 → 유치원 가입 승인 → 아이 연결 승인을 분리한다.** 세 단계가 모두
   끝나야 보호자 화면에서 아이 자료를 볼 수 있다.
5. **교사 권한도 역할과 반 배정을 분리한다.** 교사 가입이 승인되어도 담당 반
   배정 전에는 어떤 반 자료도 볼 수 없다.
6. **졸업·퇴원과 계정 삭제를 분리한다.** 한 아이가 졸업해도 형제자매가 재원
   중이면 보호자 계정은 유지한다.

## 가입 화면에서 받는 정보

### 모든 신청자

- 신청 역할: 학부모/보호자 또는 교사
- 아이디와 비밀번호
- 신청자 이름
- 전화번호
- 전화번호 확인용 SMS 안내 동의

### 학부모/보호자

- 아이 한국 이름 또는 영어 이름 중 하나 이상
- 아이 생년월일
- 아이와의 관계
  - 아버지
  - 어머니
  - 할머니
  - 할아버지
  - 기타(직접 입력)
- 법적 부모 또는 법적 보호자라는 본인의 응답
  - 예
  - 아니요
  - 잘 모르겠어요

가입 신청 단계에서는 양육권 서류, 신분증, 주소, 아이 전화번호, 아이 이메일,
정확한 위치를 받지 않는다. 필요한 민감 서류가 있다면 승인 후 별도의 제한된
절차에서 다룬다.

## 미국 전화번호 처리

- 화면 기본 국가는 미국/캐나다 `+1`이다.
- `(714) 555-0123`처럼 입력·표시한다.
- 서버에는 `+17145550123` 같은 E.164 형식으로 저장한다.
- OTP 자체는 Giving Tree 데이터베이스나 로그에 저장하지 않는다.
- 인증 요청, 재요청 제한, 만료, 실패 횟수, CAPTCHA는 실제 SMS 공급자와
  서버가 처리한다.
- 전화번호가 바뀌면 기존 인증 상태를 즉시 무효화한다.
- 가족이 같은 연락처를 사용할 수 있으므로 연락처 전화번호 자체는 전역
  고유값으로 강제하지 않는다. 나중에 전화번호를 로그인 ID로 사용할 경우의
  고유성은 별도로 결정한다.
- OTP 수신 동의와 공지·사진 반복 SMS 수신 동의는 서로 다른 기록으로 둔다.
  반복 SMS는 기본값을 꺼짐으로 유지한다.

현재 시제품은 실제 문자를 보내지 않고 화면 흐름만 확인한다. 실제 SMS는
Twilio, Vonage 같은 공급자 비용이 발생하므로 사용자가 승인하는 유료 단계까지
연결하지 않는다.

## 승인 흐름

1. 신청자가 계정·연락처·아이 정보를 제출한다.
2. 계정은 `pending` 상태이며 유치원 자료 접근 권한이 없다.
3. 원장은 신청 정보와 원아/교직원 명단을 비교한다.
4. 전화번호 확인 상태를 확인하되, 이를 보호자 자격 증명으로 사용하지 않는다.
5. 보호자 신청은 각 아이 연결을 따로 승인한다. 형제자매 중 한 명만 승인할
   수도 있다.
6. 교사 신청은 계정 승인 후 담당 반과 세부 권한을 별도로 지정한다.
7. 승인·거절·반 배정·권한 변경은 모두 관리 기록에 남긴다.

승인, 권한 부여, 접근 중지, 삭제 예약은 클라이언트가 테이블을 직접 수정하지
않고 서버 함수에서 권한 재확인과 감사 기록을 하나의 트랜잭션으로 처리한다.

## 주요 테이블

| 테이블 | 역할 |
|---|---|
| `profiles` | 로그인 사용자의 전역 프로필과 아이디 |
| `phone_contacts` | E.164 전화번호, 인증 상태, OTP 안내 동의 |
| `schools` | 유치원 |
| `school_memberships` | 사용자의 유치원 소속과 활성 상태 |
| `membership_roles` | 한 소속에 부여된 원장·교사·보호자 역할 |
| `classes` | 반 |
| `children` | 아이 기본 정보 |
| `enrollments` | 아이의 반과 재원 기간 |
| `signup_applications` | 가입 신청과 심사 상태 |
| `application_child_claims` | 신청자가 연결을 요청한 아이별 정보 |
| `guardian_child_links` | 승인된 보호자–아이 관계와 법적 권한 검토 상태 |
| `staff_class_assignments` | 교사 담당 반 |
| `capability_grants` | 공지·식단 등 세부 위임 권한 |
| `communication_consents` | 목적별 SMS 동의·철회 기록 |
| `lifecycle_actions` | 접근 중지, 재원 종료, 삭제 예약 |
| `audit_events` | 변경 이력 |

## 서버 접근 규칙

- 승인 대기 사용자는 자기 신청서만 볼 수 있다.
- 보호자는 승인된 `guardian_child_links`의 아이만 볼 수 있다.
- 교사는 현재 유효한 `staff_class_assignments`의 반만 볼 수 있다.
- 교사에게는 양육권·법적 보호자 문서나 전체 전화번호를 기본 공개하지 않는다.
- 원장은 자기 유치원만 관리할 수 있다.
- 중지·종료된 소속은 남아 있는 로그인 세션이 있어도 즉시 RLS에서 차단한다.
- 클라이언트가 선택한 역할이나 수정 가능한 사용자 메타데이터를 권한 근거로
  사용하지 않는다.
- 마지막 활성 원장 계정은 스스로 중지·강등·삭제할 수 없게 서버에서 막는다.
- 사진은 나중에 비공개 저장소와 짧은 만료 접근 링크를 사용한다.
